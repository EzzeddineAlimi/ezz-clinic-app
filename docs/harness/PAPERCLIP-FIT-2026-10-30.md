## Verified boundaries and methodology

GitHub API reports [Paperclip](https://github.com/paperclipai/paperclip) as public, MIT licensed, TypeScript-primary, approximately **108,975 stars and 18,042 forks** at this snapshot. The recursive tree contained **14,030 entries** (12,983 files), not 14,030 reviewed files. We inspected its architecture, heartbeat/checkout, execution policy, approvals, routines, budget, agent adapters, authentication, secrets, deployment modes, PR-check skills and representative source/tests. **This is not a line-by-line security audit of the whole upstream repository, nor proof that every documented feature or security control works under attack.** GitHub stars indicate interest, not suitability or safety.

Paperclip is an **agent-work management control plane**, not a healthcare EHR/clinical app. Its [architecture](https://github.com/paperclipai/paperclip/blob/18b1637b6371a6a6adade857e2a73654ee626fef/docs/start/architecture.md) adds a Node/Express API, React UI, PostgreSQL/PGlite, adapters, jobs, credential handling and a scheduler. [Codex](https://github.com/paperclipai/paperclip/blob/18b1637b6371a6a6adade857e2a73654ee626fef/docs/adapters/codex-local.md) is a **Codex CLI adapter**; the [HTTP adapter](https://github.com/paperclipai/paperclip/blob/18b1637b6371a6a6adade857e2a73654ee626fef/docs/adapters/http.md) calls an accessible endpoint. EZZ's existing ChatGPT scheduled tasks and external Muse/Muse Ons reviews are **not shown to be Paperclip-compatible runnable endpoints**. Installing Paperclip would not automatically connect them or grant independent review.

## Adopt now (small existing-system improvements, not a second platform)

**Scope:** the existing `docs/harness/TASK_CONTRACT.md` and GitHub PR template record a minimal, machine-consumable *conceptual* run-to-task handoff: the claimed owner/claim evidence, exact run ID when available, explicit run outcome, truthful check/CI evidence, task acceptance state and next actor. This is a documentation/process gate, **not an automated runtime checkout, automatic approval, or security policy enforcement**. Existing Codex/COO tasks already contain overlap/ownership prohibitions; do not duplicate schedules or introduce a new planner.

**Checklist for every active worker:**

1. Resolve task ID to **founder-approved V1 scope**, actual current main SHA, current assignee and competing draft/PR. If scope or ownership conflicts, mark `BLOCKED` and stop that slice.
2. When parallel writers could collide, use **one verifiable exclusive claim** only if the tool supports atomic create-if-absent; verify readback and do not silently steal/retry a conflict. A GitHub issue comment alone is **not** atomic checkout.
3. Record **run status** (`IMPLEMENTED_DRAFT`, `REVIEW_ONLY`, `BLOCKED`, `NO_APPROVED_WORK`, `FAILED`) separately from **task status** (`OPEN`, `IN_REVIEW`, `DONE_WITH_ACCEPTANCE`). Don't upgrade to acceptance based on a green CI run.
4. Independently validate exact-head and integrated-base CI, source/contract negative cases, ancestry and reviewer verdict at the **same head** before a permitted merge. No self-review, phantom review or implied production clearance.
5. Publish exactly one attributable handoff with what changed, what actually ran, unresolved risks, next owner and source URLs. For cross-worker messages use a unique-ID `appendCells` row in Mission Control `MODEL_HANDOFF_LOG`, then read back the row; keep independent review evidence in `UX_MODEL_REPORTS`. Do not reuse the full legacy `MODEL_INBOX` lanes or infer that an external model received a message.
6. Report **cost unknown** without authoritative usage data. Existing model subscription and native automation costs are not measured or capped by this document.

## What not to copy

- Paperclip's separate Express/PostgreSQL application, PGlite database, job scheduler, CLI adapters, secret vault, organizational hierarchy, auto-hiring, external webhook listeners, third-party plugins or company-level agent spending controls. For our current team these duplicate services and grow the security/operational surface.
- Its health-related assumptions: **Paperclip provides no evidence of Tunisian dental clinical/fiscal/CNAM approval or independent physical cash reconciliation**; the 61 V1 acceptance items and all external clinical/payment/security gates remain open.
- Any claimed provider cost or 24/7 agent availability without runtime evidence. Do not upload PHI or credentials to generic agent prompts, logs, dashboard, or public GitHub.

## Decision gates / future reconsideration

Reconsider an isolated **fictional-only** Paperclip pilot only if the team has a verified recurring conflict or missed-work problem that GitHub claim discipline and the existing Sheet cannot fix; usable authorized Codex/HTTP runner endpoints; demonstrated least-privilege agent credentials; secure authenticated/private deployment with contained secrets; measurable benefit exceeding ongoing platform cost; and independently reviewed failure-injection tests. Do not change current automations or model review authority as part of a research evaluation.
